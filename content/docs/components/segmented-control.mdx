## Installation

```npm
npx shadcn@latest add @videorc/segmented-control
```

## Usage

```tsx
import { SegmentedControl } from "@/components/ui/segmented-control";
```

```tsx
<SegmentedControl
  aria-label="Theme"
  onValueChange={setTheme}
  options={[
    { label: "Light", value: "light" },
    { label: "Dark", value: "dark" },
    { label: "System", value: "system" },
  ]}
  value={theme}
/>
```

Which control when:

- **Segmented control** chooses a value: theme, fit, corner, kind of cut.
- [Tabs](/docs/components/tabs) switch a view, a page or a pane with its own content.
- [Toggle group](/docs/components/toggle-group) is for filter chips: several on at once, or a filter row.
- A [Switch](/docs/components/switch) is for a boolean, and a one-shot action is a [Button](/docs/components/button).

## Examples

### Sizes

`size="sm"` (20 px segments) fits a toolbar or a small window. `activationMode="manual"` makes the arrow keys only move focus, and Space or Enter choose: use it when a change is heavy, such as switching a live scene.

### Disabled with a reason

A disabled control always says why. Pass `disabledReason` with `disabled` and the reason shows as a line under the control and describes the group.

## Theming

Segmented control wears the same track and segment as [Tabs](/docs/components/tabs). Both read it from `tabs-variants`, a small module with no Base UI import, so a segmented control costs a window's first bundle nothing:

- `tabsListVariants({ variant })` is the track.
- `tabsTriggerBaseClassName` is one segment, before its selected state.

| Token or attribute | Meaning |
| --- | --- |
| `bg-foreground/5`, `ring-border` | The recessed track |
| `chrome-plate` | The checked segment, keyed off `aria-checked` |
| `rounded-row`, `rounded-chip` | The track and a segment |
| `min-h-control`, `min-h-6` | The `default` and `sm` track heights |
| `data-checked`, `data-unchecked` | On every segment, as a Base UI radio marks it |
| `data-size` | On the track: `default` or `sm` |

## Keyboard

| Key | Action |
| --- | --- |
| `Tab` | Lands on the checked option, or the first enabled one; `Tab` again leaves the group |
| `ArrowRight`, `ArrowDown` | Moves to the next enabled option, wrapping; checks it unless activation is manual |
| `ArrowLeft`, `ArrowUp` | Moves to the previous enabled option, wrapping; checks it unless activation is manual |
| `Home`, `End` | Moves to the first or last enabled option |
| `Space`, `Enter` | Checks the focused option |

## Accessibility

It follows the WAI-ARIA radio group pattern: the track is a `radiogroup` and each option a `radio` with `aria-checked`. Name it with `aria-label`, or put it in a [Field](/docs/components/field): the Field's label names the group through `aria-labelledby` unless the group carries its own `aria-label`. While disabled with a reason, the group is `aria-disabled` and `aria-describedby` the reason, so a screen reader hears why.

`onValueChange` fires only with a newly checked value. An option's own `onClick` still runs on the checked option: the hook for choosing it again (replay, re-apply).
