## Installation

```npm
npx shadcn@latest add @videorc/tooltip
```

## Usage

```tsx
import {
  Tooltip,
  TooltipContent,
  TooltipProvider,
  TooltipTrigger,
} from "@/components/ui/tooltip";
```

```tsx
<Tooltip>
  <TooltipTrigger
    render={<Button aria-label="Keep on top" size="icon" variant="ghost" />}
  >
    <PinIcon />
  </TooltipTrigger>
  <TooltipContent>Keep on top</TooltipContent>
</Tooltip>
```

Mount one `TooltipProvider` around each window. Tooltips under it share a delay group: once one is open, moving to the next opens it at once. A tooltip outside every provider still works, with its trigger's own 600 ms.

## Anatomy

```tsx
<TooltipProvider>
  <Tooltip>
    <TooltipTrigger />
    <TooltipContent />
  </Tooltip>
</TooltipProvider>
```

## Theming

| Token or attribute | Meaning |
| --- | --- |
| `glass-float-tooltip` | The tooltip tier: the window's solid tone, a 1 px rim and the float drop |
| `rounded-row` | 8 px corners |
| `text-xs` | 12 px text, never an inverted pill |
| `data-open`, `data-closed` | Fades and scales from 0.98 in 100 ms, with no slide |
| `data-side` | The side it opened on |

## Keyboard

| Key      | Action                                 |
| -------- | -------------------------------------- |
| `Tab`    | Focusing the trigger opens its tooltip |
| `Escape` | Closes the tooltip                     |

## Accessibility

A tooltip is never the only place a fact lives, and `title=` is not an information channel. An icon-only trigger still needs its own `aria-label`: the tooltip repeats the name for sighted users. A disabled control takes no hover, so explain it with [Disabled reason](/docs/components/disabled-reason).
